# 自测说明

没有真实环境的时候，用虚拟数据体系化检查 skill 的文本迭代有没有破坏核心纪律。

## 组成

- `virtual-project.md` 一个固定的虚拟项目，假仓库、假缺陷系统、假 bug。
- `checklist.md` 不变量清单，每次改动后逐条检查。
- `run-XXX.md` 每次自测的运行记录和发现。

## 怎么跑

1. 读 `virtual-project.md`，进入虚拟环境。
2. 以使用者的身份，按 SKILL.md 和 loop.md 走一遍完整循环。
3. 用 depth-gate 给每条虚拟 bug 打分，检查结论有没有被正确拦住。
4. 用 retrospective 对昨天的单复盘，检查有没有强制回答第三问。
5. 对照 checklist 逐条打勾，记录任何纪律被削弱的发现。
6. 把结果写进新的 run-XXX.md。

## 脚本自测

六个脚本的冒烟测试在 run-002.md，照着命令直接跑。改脚本之后先跑一遍，别带着坏脚本开工。

## 目的

不是为了证明 skill 是对的，是为了每次改文字改脚本之后，能客观地发现哪里退化了。
