# 不变量清单

每次改完文字、改完脚本，逐条检查下面这些。这是 skill 的骨头，任何一条被削弱就是退化，要回退或修正。

## A 循环完整

- [ ] loop.md 的顺序固定，拉单，逐条分析，可选修复提交，最后写进文件
- [ ] 复盘按需做，有昨天的分析才对账，没有或用户只要新单就直接分析
- [ ] 逐条分析的第一步是扫经验库偏差表

## B 证据门槛

- [ ] depth-gate 的工序保底在，适用的检查动作至少做一半
- [ ] 结论等级看证据置信度，不由做了多少分析步骤决定
- [ ] 一条 bug 的状态仍然只有五个，无法定论和信息不足是降级态，不是结论态
- [ ] 检查动作的每一项都不依赖特定项目类型，没有特定工程或公司的专属概念

## C 复盘

- [ ] retrospective 仍然强制写三部分，我的结论、人类后来做了什么、我为什么没能得出
- [ ] 只写对错不写为什么，仍然被明令禁止

## D 基本原则

- [ ] principles 仍然是跟项目类型无关的调试原则，不依赖任何语言、框架或项目类型
- [ ] 每条原则仍然覆盖四件事，是什么、为什么、怎么做、真实例子
- [ ] 例子是匿名启发，不出现真实公司名或工程名

## E 零敏感内容

- [ ] 全文搜不到任何真实的工具名、仓库名、域名、团队名、字段名
- [ ] 项目类型专属概念只以匿名例子的身份出现

## F 可执行

- [ ] 每一条纪律都能回答我具体要做什么动作
- [ ] 不存在看起来有道理但没法执行的话

## G 环境探测

- [ ] bootstrap 仍然问四件事，代码仓库、缺陷系统、每天从哪里拉单（要具体能打开的位置）、运行证据
- [ ] bootstrap 仍然要求验一遍，拉单、pull、拿运行证据三步都通才开工
- [ ] 配置仍然不允许写凭证正文，只许用环境变量名引用

## H 经验库

- [ ] lessons 偏差表仍然有六个字段，业务模块、偏差类型、示例、教训、分类、验证路径
- [ ] 复盘产物模板仍然带三部分加提炼的教训
- [ ] 教训必须是动作，不许写没法执行的话

## I 修复提交分级

- [ ] autonomy-ladder 仍然有四级，L0 到 L3，每一级有允许和禁止
- [ ] 提交验证铁律仍然在，不信 exit code，要看成功标记

## J 脚本可用

- [ ] 所有脚本只依赖 Python 标准库，不装第三方包
- [ ] 每个脚本在虚拟数据上跑通，见 run-002.md
- [ ] 脚本不硬编码任何凭证和地址，地址从参数和环境变量来

## K 运行证据

- [ ] runtime-evidence 的坑是机制无关的，不写死具体浏览器、自动化库、路径
- [ ] 拿不到分两种，确实没有和没下载成，被明确区分
- [ ] 机制层由项目适配决定，skill 只写坑不写方法

## L 结构与冷启动

- [ ] 参考文档都在 references/ 下，没有 core/ 等旧目录名
- [ ] 经验库偏差表按业务模块索引，字段齐全
- [ ] cold-start 存在，冷启动按业务模块组织历史单
