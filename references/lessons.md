# 经验库怎么写

经验库是 skill 越用越准的载体。记的是复盘对账时发现的差距，缺陷单里别人的解决结论，和 skill 上次给的分析结论，两边对不上，就把教训记进来。分析新 bug 之前，先扫一眼偏差表，看有没有命中的，有就直接按验证路径走。

## 文件放哪

经验库文件叫 `lessons.md`，放在 `project-config.md` 旁边，同一个目录。第一次写的时候用 `scripts/lesson_append.py` 追加，脚本会自动建文件、建表头。

## 长什么样

```markdown
# 经验库

## 偏差表

| 业务模块 | 偏差类型 | 示例 | 教训 | 分类 | 验证路径 |
|----------|----------|------|------|------|----------|
| 订单页 | 代码逻辑看成配置问题 | BUG-101 | 先查布局参数，再查代码逻辑 | 显示 | 先查锚点参数 |
```

## 偏差表六个字段

| 字段 | 写什么 |
|------|--------|
| 业务模块 | 这条 bug 属于哪个业务模块，比如订单、支付、登录。同一模块的教训优先复用 |
| 偏差类型 | 从想当然到实际的转变。比如代码逻辑看成配置问题，性能猜测看成数据时序 |
| 示例 | 这条 bug 的匿名编号，方便回查 |
| 教训 | 一句话，下次能直接套用 |
| 分类 | 属于哪一类症状，显示、逻辑、数据、资源 |
| 验证路径 | 正确做法是什么。不只写根因，要写动作 |

## 追加规则

- 一条一行，用 `scripts/lesson_append.py` 追加，格式不会错。
- 同一类偏差只留最新一条。已有同类记录就先更新，不叠着堆。
- 教训必须是一个动作，别写要细心、要注意这种没法执行的话。
- 每周整理一次。把同类教训归到一起，能合成原则的合成原则，能变成检查项的变成检查项。

## 复盘产物模板

每天复盘完，当天报告里固定带一段。

```markdown
## 复盘记录

### BUG-xxx
- 昨天我的结论。写了什么。
- 人类后来做了什么。改了什么，转给了谁，最终根因。
- 我为什么没能得出。人类用的什么方法，我为什么没用，如果当时做了会怎样。
- 提炼的教训。一句话，写进偏差表。
```

## 怎么用

分析一条 bug 前，先看偏差表里有没有同一业务模块的记录，再看分类和验证路径。命中的直接按验证路径走，省掉重新踩坑的时间。复盘时新发现的偏差，当天就追加进去，别攒着。
