# 冷启动，先学一遍历史

第一次部署，或者想快速熟悉这个项目的业务，走一遍冷启动。目的不是修 bug，是把历史单吃进去，建起按业务模块组织的经验库。

## 前提

project-config.md 配好了，拉单位置能拉到历史单。业务模块怎么分，问用户要一份列表，或者从单子标题里归纳。

## 步骤

1. 从拉单位置，按业务模块分批拉已关闭的历史单。已关闭的单才有最终结论，能比对。
2. 每个业务模块的单子放到一起，一次处理一个模块。
3. 逐条过打点表分析，给结论。
4. 复盘，对比评论里的修改，找出 skill 结论和实际修法的差距。
5. 差距按业务模块写进经验库。
6. 全部模块过完，冷启动结束。之后的日常循环，分析某个模块的单子前，先读那个模块的经验。

## 注意

- 历史单里拿不到运行证据的，如实标信息不足，别硬分析。
- 冷启动是批量活，慢一点没关系，重点是建库的质量，不是数量。
- 一次冷启动过不完，就按模块分批，下次接着来。
